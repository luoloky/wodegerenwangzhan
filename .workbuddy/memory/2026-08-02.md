## 第二轮优化（用户反馈：视频要往下/向文字居中、首屏滚动仍卡）

### 根因修正
- 上一轮只靠 IntersectionObserver（>10% 离屏才暂停），滚动首屏**全过程**视频仍在解码、72px/44px 两层模糊背景仍持续重绘 → 滚动仍卡。
- 本轮改为：**滚动进行中**（window scroll 事件，passive）即给 `.hero` 加 `.is-scrolling`，暂停视频解码 + 暂停 aurora/fog 模糊动画；停手 160ms 后移除类并恢复播放。可见性(IO)与滚动状态结合决定播放（sync 函数）。

### 改动
- **Hero.jsx**：重写 useEffect，合并 IntersectionObserver 与 scroll 节流逻辑（scrollTimer 160ms 防抖）。
- **Hero.css**：
  - `.hero__video` 的 `object-position` 改为 `center 72%`（画面重心下移、横向居中，落在文字区域）。
  - 新增 `.hero.is-scrolling .hero__bg-aurora, .hero.is-scrolling .hero__bg-fog { animation-play-state: paused }`。

### 验证
- dev server 仍 HTTP 200；Hero.jsx / Hero.css 编译通过（200）。已重新打开预览。

## 第三轮优化（用户反馈：仍很卡、视频还是太高 —— 上一版几乎无效）

### 关键诊断
- 确认上一版改动确实已生效（线上 curl 验证：object-position center 72%、is-scrolling 逻辑在、blur(72/44px) 仍在）。
- 结论：滚动卡顿头号元凶是 **`.hero__bg-aurora` 的 `filter: blur(72px)` 与 fog 的 `blur(44px)` 大半径模糊层**。暂停动画只停掉 transform 位移，但模糊纹理作为合成层在滚动时仍被每帧重绘/合成 → 卡顿照旧。window scroll 事件无 Lenis 干扰，正常触发。

### 改动（Hero.css）
- **彻底移除 aurora 的 `filter: blur(72px) saturate(115%)`**：改用本身就柔和的径向渐变（提高 alpha 补偿柔和度），元素 inset 从 -25% 缩到 -10%，滚动合成成本骤降。
- **fog 的 `filter: blur(44px)` → `blur(18px)`**，inset 从 -10% 收到 0；保留轻微模糊维持条纹质感。
- **视频 object-position `center 72%` → `center 90%`**：画面重心进一步下移。
- 保留上一轮 `.is-offscreen` / `.is-scrolling` 暂停逻辑（滚动时视频暂停解码 + 模糊动画停）。

### 验证
- 线上 curl 确认：object-position center 90%；aurora 已无 blur 滤镜（仅 fog 的 18px）；dev server HTTP 200。已重开预览。

### 经验沉淀
- 全屏背景的 `filter: blur(大半径)` 是滚动卡顿最常见且最易被忽略的根因；优化要「去滤镜 / 缩小模糊层」而非「暂停动画」。
- 修改后务必 curl 线上模块确认改动真正生效，避免凭感觉判断。

- 调位置口诀：Y 越小越靠下、越大越靠上；当前 45%，要更低减到 ~35%，要更高加到 ~55%。
